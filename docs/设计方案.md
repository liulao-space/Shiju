# 拾句 · 产品设计方案

> 在任何地方选中一段文字，浮出一个「收录」按钮，点一下存进本地卡片库。
> 灵感一闪而过的时候，也有地方可以放下。

- 文档版本：v3.0（依据 Easydict 实机拆解 + 源码调研，修正 v2.0 的技术误判）
- 日期：2026-09-18
- 状态：技术路线已确认可行

## 一、命名

**主选：拾句**

- `拾`——弯腰捡起，把散落的东西收好。动作感明确，且比「收藏」「收录」更轻。
- `句`——既是网页上复制的句子，也是脑子里蹦出来的那句话。同时覆盖两个使用场景。
- 两字双音节，好念好记，输入法无需翻页。
- 图标方案：菜单栏直接用一个「拾」字，汉字单字图标在小尺寸下辨识度远高于抽象图形。
- 标语：**把值得留下的话，拾起来。**

**备选：拾萤**——取「灵感如萤火，一闪就没了，替你收着」。更诗意，但功能指向不如「拾句」明确。

**英文名：Glean（拾穗）**——语义精准，即「收集他人遗漏的细小价值」。
注意与同名企业搜索产品撞名，仅自用无妨，考虑上架需另选。

### 2.3 悬浮按钮的实现（源码级）

**窗口类 `EZPopButtonWindow`（Objective-C）：**

```objc
- (instancetype)init {
    NSWindowStyleMask style = NSWindowStyleMaskBorderless;
    if (self = [super initWithContentRect:CGRectZero styleMask:style
                                  backing:NSBackingStoreBuffered defer:YES]) {
        self.level = NSNormalWindowLevel;
        self.backgroundColor = NSColor.clearColor;
        // ...
    }
    return self;
}

- (BOOL)canBecomeKeyWindow  { return NO; }
- (BOOL)canBecomeMainWindow { return NO; }
```

**这是整个方案最关键的四行代码。**

用无边框普通窗口，重写两个方法返回 `NO`，窗口就永远不会成为 key window，
也就永远不会抢走原应用的焦点。原应用不失焦，选区就不会被系统清除。

v2.0 方案里建议的 `NSPanel` + `.nonactivatingPanel` 是绕远路了，这个做法更直接。

**显隐控制 `PopButtonVisibilityController`（Swift）——自动收起逻辑：**

| 触发条件 | 行为 | 设计意图 |
|---|---|---|
| 累计滚动超过 80pt | 收起 | 你在继续往下读，不需要它 |
| 鼠标移出按钮外扩 40pt 的区域 | 收起 | 你已经走开了 |
| 上一个事件是 ⌘C | **不收起** | 避免刚复制完按钮就消失 |
| 静置 4s | 淡出 | 兜底 |

> **实现后补记（2026-09-20）**：上表本身不足以让规则「不烦人」。
> 实际跑起来出现过「按钮显示一下就消失」，根因是**位置用了过期坐标**——
> `mouseUp` 时记下的鼠标位置，要等异步取词（AX 查窗口标题 + AppleScript 取
> 浏览器 URL + 模拟 ⌘C，几十到几百毫秒）跑完才被用来摆按钮，
> 那时用户的手早就动了。于是按钮落在光标之外，紧接着的 `mouseMoved`
> 立刻把它收掉。
>
> 两条修正：**位置在出现的那一刻现取鼠标坐标**；**出现后 0.6s 内不理会
> 「鼠标移开」**。另外外扩容差从 24pt 提到 40pt——原值下光标往上移 14pt 就出界。
>
> 教训：**「移开就收起」这类规则，必须先保证「按钮确实出现在用户手边」**，
> 否则它不是防打扰，而是随机消失。

**触发判定 `TriggerEvaluator`（Swift）——什么时候弹：**

| 条件 | 判定 |
|---|---|
| 最近 3 个事件全部是 `leftMouseDragged` | 拖拽选择刚结束 → 触发 |
| 0.5 秒内出现 4 个 Command 键事件 | 双击 ⌘ → 触发 |

**这直接回答了「每次选中文字都弹东西会不会烦」这个疑虑。**
它不是「一有选区就弹」，而是「你明确完成了选择动作才弹」，
并且你一滚动鼠标它就收起来。这是打磨过的设计，不是粗暴实现。

**全局事件监听 `EventTapMonitor`：**

使用 `CGEvent.tapCreate`，`options: .listenOnly`（只监听，不拦截、不修改事件流），
监听 `keyDown`。并处理 `tapDisabledByTimeout` 自动重启用。

### 2.4 取词策略（SelectedTextKit）

`SelectedTextKit` 把「在任意应用拿到选中文本」抽成了独立库，支持五种策略，
可组成有序降级链：

| 策略 | 原理 | 适用 |
|---|---|---|
| `.accessibility` | 辅助功能 API 直接读选区 | 大多数原生应用，最快 |
| `.menuAction` | 触发菜单栏的「拷贝」项 | 辅助功能受限时绕过 |
| `.shortcut` | 模拟 ⌘C | 通用兜底 |
| `.appleScript` | AppleScript 读浏览器选区 | Safari / Chrome / Firefox |
| `.auto` | 智能降级（accessibility → menuAction） | **推荐默认** |

内置两项重要保护：

- **剪贴板保护**：备份并还原用户原有剪贴板，临时任务不污染用户内容
- **提示音静音**：模拟按键时临时降低音量，避免系统发出哔声

调用方式极简：

```swift
import SelectedTextKit

let textManager = SelectedTextManager.shared
if let text = try await textManager.getSelectedText(strategy: .auto) {
    print(text)
}
```

- 仓库：https://github.com/tisfeng/SelectedTextKit
- 许可证：**MIT**
- 要求：macOS 11.0+ / Swift 5.7+
- 活跃度：高（最新提交 2026-09-06，最新版本 2.6.7）

### 2.5 许可证风险（重要）

| 项目 | 许可证 | 约束 |
|---|---|---|
| Easydict | GPL-3.0 | 抄它的代码 → 你的应用也必须 GPL 开源 |
| SelectedTextKit | MIT | 自由使用，闭源亦可 |

**结论：用 `SelectedTextKit`，不要抄 Easydict 的代码。**
只承担 MIT 义务，不触发 GPL 的传染性。

## 三、修正后的技术架构

```
任意应用选中文本
        ↓
[ 触发层 ]  CGEventTap 只监听，不改事件流
   鼠标拖拽选择结束（最近 3 事件均为 leftMouseDragged）
   或 双击 ⌘（0.5s 内 4 个 Command 键事件）
        ↓
[ 取词层 ]  SelectedTextKit（MIT，直接依赖）
   .auto → accessibility → menuAction → shortcut 逐级降级
   自带剪贴板备份还原 + 提示音静音
        ↓
[ 展示层 ]  无边框 NSWindow
   canBecomeKeyWindow / canBecomeMainWindow 返回 NO（绝不抢焦点）
   自动收起：滚动 > 80px / 鼠标移出 / 例外：上一个事件是 ⌘C
        ↓
[ 存储层 ]  SQLite + FTS5
   ~/Library/Application Support/拾句/library.db
```

### 3.1 技术栈

- 语言：**Swift**（不再需要 Python 原型阶段，因为核心难点已有现成库）
- UI：AppKit（悬浮窗与菜单栏）+ SwiftUI（卡片浏览面板）
- 形态：`LSUIElement = true` 菜单栏应用
- 沙盒：**必须关闭**
- 签名：自用可运行未签名版本；分发需签名 + 公证

### 3.2 数据模型

```sql
CREATE TABLE snippets (
  id            TEXT PRIMARY KEY,      -- UUID v4
  text          TEXT NOT NULL,         -- 正文
  text_hash     TEXT NOT NULL,         -- 归一化后 SHA1，用于去重
  source_app    TEXT,                  -- 来源应用名
  source_title  TEXT,                  -- 页面/文档标题
  source_url    TEXT,                  -- 仅浏览器可获取，允许为空
  captured_at   INTEGER NOT NULL,      -- 毫秒时间戳
  starred       INTEGER DEFAULT 0,
  deleted_at    INTEGER                -- 软删除，7 天可恢复
);

CREATE VIRTUAL TABLE snippets_fts USING fts5(text, source_title);
```

- `text_hash` 归一化规则：去首尾空白 → 连续空白折叠为单空格 → 转小写
- `source_url` 为空时，UI 降级为只显示应用名
- 所有数据仅存本地，无账号、无云端、**无遥测**

> 与 Easydict 的一个设计分歧：Easydict 集成了 Firebase Analytics 与 Sentry。
> 拾句定位是纯个人工具，不引入任何遥测。

## 四、必须处理的边界情况

1. **绝不自动保存。** 必须用户点击，防止卡片库被无意义内容淹没。
2. **安全输入保护。** 检测 `IsSecureEventInputEnabled()`，密码框聚焦时
   一律不捕获、不弹按钮、不模拟按键。
3. **敏感应用忽略名单。** 密码管理器、银行、支付类应用默认不弹按钮。
4. **剪贴板还原。** `SelectedTextKit` 的 `.shortcut` 策略已内置此保护，
   若自行实现则必须完整保存并写回原剪贴板（含所有数据类型）。
5. **不兼容应用清单。** Canvas 渲染类应用（Google Docs、Figma）读不到选区，
   需维护已知不支持名单并在设置中展示，避免用户误判为 Bug。
6. **重复提示节流。** 同一段文本 60 秒内只提示一次。
7. **纯文本降级。** MVP 只处理纯文本。
8. **菜单栏图标常驻。** `LSUIElement = true` 意味着没有 Dock 图标，
   必须保证菜单栏图标始终可见，否则用户无法退出应用。

## 七、验收标准

1. 在 Safari、Terminal、备忘录、微信中分别拖拽选中一段文字，
   1 秒内浮出收录按钮，且**原应用焦点不丢失、选区不消失**。
2. 点击按钮后，菜单栏面板中能看到该卡片，含来源应用名与时间。
3. 在 Safari 中收录的卡片，额外包含页面标题与可点击链接。
4. 收录后，剪贴板中仍是用户此前手动复制的内容（未被污染）。
5. 聚焦密码输入框时选中文字，不弹按钮、不捕获任何内容。
6. 选中文字后向下滚动页面超过 80px，按钮自动消失。
7. 库内累计 5000 条时，搜索响应时间低于 100ms。
8. 断网状态下全部功能正常。

## 八、展示层与实现语言选型（v3.1 新增）

### 8.1 SwiftBar 评估结论：不可行

SwiftBar 的本质是「脚本输出 → 菜单栏下拉」，插件就是一段输出文本的脚本。

经查证其官方文档，**不具备**以下能力：

| 需求 | SwiftBar 支持 |
|---|---|
| 响应文本选择（捕获层） | ❌ 文档完全未提及 |
| 浮动窗口 | ❌ 不支持 |
| 菜单内搜索输入框 | ❌ 不支持 |
| 卡片式布局 | ❌ 仅支持单行文本条目 |

它支持的渲染参数只有：`color` / `font` / `size` / `md` / `ansi` / `image` /
`sfimage` / `checked` / `tooltip` / `badge` / `href` / `bash` / `shortcut` 等，
本质上都是「一行文字 + 一个点击动作」。

**唯一有价值的发现**：`webview=True` 参数可以把一个网页嵌进菜单下拉里，
`webvieww` / `webviewh` 控制尺寸。理论上能用它承载卡片界面，但属于冷门路径，
且菜单追踪模式下的交互（输入、滚动）稳定性需实测。

**结论：SwiftBar 不能作为拾句的实现方案。**

### 8.2 Hammerspoon 评估结论：可行，但只适合原型

Hammerspoon 是 Lua 脚本自动化工具，四层能力都覆盖得到：

| 需求 | Hammerspoon 模块 | 评估 |
|---|---|---|
| 读选中文本 | `hs.axuielement` | ⚠️ 只有通用属性访问，无封装 |
| 检测拖拽选择结束 | `hs.eventtap` | ✅ 可用 |
| 悬浮按钮 | `hs.canvas` | ⚠️ 窗口焦点行为需实测 |
| 全局快捷键 | `hs.hotkey` | ✅ 可用 |
| 卡片界面 | `hs.webview` | ✅ 可用，能渲染 HTML |
| 菜单栏图标 | `hs.menubar` | ✅ 可用 |

**三个硬伤：**

1. **取词要自己搭降级链。** `hs.axuielement` 只提供
   `attributeValue("AXSelectedText")` 这种通用访问，没有 `SelectedTextKit`
   那样封装好的五级策略，也没有剪贴板备份还原和提示音静音。
2. **官方文档明确警告**：从拥有大量后代元素的元素（如浏览器）开始遍历辅助功能树，
   **可能阻塞 Hammerspoon，极端情况超过 5 分钟**。
3. **必须额外安装宿主**（Hammerspoon 约 50MB），且需常驻运行并授予辅助功能权限。

**结论：Hammerspoon 适合做「今天就能跑起来」的原型，不适合做最终产品。**

### 8.3 展示形态对比

| 形态 | 实现方式 | 优点 | 缺点 |
|---|---|---|---|
| 菜单栏下拉列表 | SwiftBar / `hs.menubar` | 最轻，零窗口管理 | 无搜索框、无卡片感、长列表难用 |
| 菜单栏 + WebView | SwiftBar `webview=True` | 菜单内即完整卡片 UI | 冷门路径，稳定性待验证 |
| **独立窗口 + WebView** | `hs.webview` / Swift WKWebView | **卡片 UI 用 HTML 写，灵活好看** | 需要窗口管理 |
| 浏览器标签页 | 本地小 HTTP 服务 | UI 开发最快 | 需起服务，不像「应用」 |

**推荐：独立窗口 + WebView。** 菜单栏图标点击唤出，窗口内是 HTML 卡片界面。

### 8.4 实现语言选型

关键认知：**「轻量级」有两个维度，容易混淆。**

- **运行时轻量**：占资源少、无运行时依赖 → **Swift 胜**
- **开发轻量**：不用编译、改完即跑 → **Lua / 脚本胜**

| 层 | 候选语言 | 推荐 |
|---|---|---|
| 捕获层（AX / CGEventTap） | Swift / Objective-C | **Swift**（唯一的最优解） |
| 捕获层（原型） | Lua via Hammerspoon | 可接受 |
| 存储层（SQLite） | 任意 | 跟随宿主语言 |
| 展示层（卡片界面） | HTML / CSS / JS | **HTML**（开发效率高一个数量级） |

**最终推荐组合：**

```
Swift 壳（捕获 + 菜单栏 + 窗口）
        +
WKWebView 渲染 HTML/CSS 卡片界面
        +
SQLite 单文件存储
```

理由：

- Swift 壳体积约 5MB，内存约 40MB，无运行时依赖 —— 这是真正的轻量
- 卡片界面用 HTML 写，比 SwiftUI 快约三倍，且改样式不用重编译
- SQLite 单文件，无服务、无账号

**替代组合（不碰 Xcode 的版本）：**

```
Hammerspoon（Lua 壳）
        +
hs.webview 渲染同一套 HTML 卡片界面
        +
SQLite 单文件存储
```

同一套分层，只把壳换成 Lua。适合先验证交互，代价是多装一个 50MB 宿主。

### 8.5 与 Easydict 联动的可行性（已排除）

曾考虑让 Easydict 的现有悬浮按钮直接把选中文本推送给拾句，避免重复实现捕获层。
实测排除：Easydict 虽有 `easydict://` URL Scheme，但其浮按钮的动作
（`startQueryText:actionType:`）硬编码为翻译查询，不支持注册自定义动作或 webhook。

**结论：捕获层必须自建。**
