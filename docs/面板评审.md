## 总评

这套 UI 的水准明显高于「随手写个面板」。多处能看出是**做过取舍**的，
不是把样式堆上去。架构（token 分层、视图切换、编辑态）是站得住的，
问题集中在几个具体的实现细节上。

## 一、做得好的地方

### 1. 阴影从文字色派生，而不是硬编码黑色

```css
box-shadow: 0 1px 2px color-mix(in srgb, var(--color-text) 22%, transparent);
```

而不是常见的 `rgba(0,0,0,.2)`。代码注释里那句「夜览/灯下加纯黑等于看不见」
说明作者清楚为什么要这么做。这是很多人想不到的一层。

### 2. 组件内零字面色值

所有颜色走 CSS 变量，10 套主题只替换一组 token，连圆角（`--radius`）
和字体族（`--font-display` / `--font-text`）一起换。这条纪律是主题系统
能撑住的前提。

### 3. `color-mix` 做 hover 底色

```css
background: color-mix(in srgb, var(--color-surface) 96%, var(--color-accent));
```

比硬编码一个浅蓝色稳——换主题时自动跟着走。

### 4. 列表视图的排版决策

把句子放在第一视觉元素，出处与时间降到下一行。注释里留了一句
「旧版『书』『古 文』就是这么塌的」——说明踩过坑并修正了。
固定宽度的左右栏确实会让短标签竖着折行。

### 5. `data-clip` 只在真的被裁掉时才加渐隐与「展开全文」

```js
c.dataset.clip = (el.scrollHeight - el.clientHeight > 2) ? '1' : '0';
```

判断条件是对的。常见错误是无条件显示「展开全文」，短句也挂着这个按钮。

### 6. Esc 逐层退出

编辑态 → 回读态 → 关详情 → 清搜索。层级顺序正确，而且注释解释了
「在输入框里按 Esc 不该把搜索词抹掉」。这个细节大部分实现会做错。

### 7. 就地编辑用虚线 hairline，而不是蓝色聚焦环

理由是「macOS 的『就地编辑』（访达重命名、备忘录）都是这种安静的提示，
不是 web 表单」。这是品味层面的判断，判断得对。

### 8. 类型化排版

`[data-kind="terminal"]` 用等宽字体且 `text-align:start`，
不跟着正文走两端对齐。中文正文用
`text-align:justify; text-justify:inter-ideograph; hanging-punctuation:allow-end`
也是 CJK 排版的正确写法。

### 9. 已经在为原生壳做准备

`-webkit-app-region: drag` 配合 `.topbar > *{ no-drag }`，
说明已经考虑无边框窗口的拖拽区。

### 10. 工程性兜底

- `applyEdits` + localStorage，让 HTML 能脱离原生壳单独在浏览器里调样式
- localStorage 全部 try/catch，注释写了「沙箱化预览环境里可能抛异常，
  不能把整个面板带崩」
- `state.touched` 让首行不会一进来就带蓝色选中轨

## 二、需要修的

### P0 — `.card::after` 热区补丁挡住了卡片视图里的所有按钮

```css
.card::after{ content:""; position:absolute; inset:0; z-index:0; }
```

**问题**：`.card` 是 `position:relative`，`::after` 是定位元素且 `z-index:0`，
它绘制在层叠顺序的「定位元素」阶段，**晚于** `.acts button` 这类静态流内元素。
命中测试取最上层元素，而伪元素的事件会派发到宿主元素 `.card`。

**后果**：卡片视图里点击「★ 星标 / 复制 / 删除」以及标签，
事件目标都会是 `.card`，于是走到 `openSheet()`——
按钮看起来能点，实际打开的是详情弹窗。

**为什么没被发现**：列表视图写了
`.grid.list .card::after{ display:none; }`，
注释还说明「行本身整条可点，不需要热区补丁」。所以在列表视图下是正常的。

**修法（一行）**：

```css
.card::after{ content:""; position:absolute; inset:0; z-index:0; pointer-events:none; }
```

更彻底的做法：`.card` 本身已经整块可点（点击处理用
`e.target.closest('.card')`），这个 `::after` 其实可以直接删掉。

### P1 — `clip()` 每次 render 都对每张卡片强制同步布局

```js
$$('.card__text', grid).forEach(el => {
  const c = el.closest('.card');
  if (c) c.dataset.clip = (el.scrollHeight - el.clientHeight > 2) ? '1' : '0';
});
```

读取 `scrollHeight` 会强制 reflow。当前链路是：
搜索框每敲一个字符 → `render()` → 重建整个 grid → `clip()` 逐张读 `scrollHeight`
→ N 次强制布局。

14 条样例数据看不出来，到 1000+ 条会明显卡顿。

**建议**：

1. 搜索输入加 debounce（约 150ms）
2. `clip()` 先批量收集元素、再统一读，避免读写交替；或改用
   `IntersectionObserver`，只在卡片进入视口时计算

---

### P1 — `dayKey()` 不是真正的自然日分组

```js
const t = new Date(Date.now() - ts);
const days = Math.floor((Date.now() - d.getTime()) / 86400e3);
```

因为 `d` 就是 `new Date(Date.now() - ts)`，所以
`Date.now() - d.getTime()` 恒等于 `ts`——也就是「距今过了多少毫秒」。
除以 86400e3 得到的是**经过了多少个 24 小时**，不是**差了几个自然日**。

**后果**：昨晚 23:50 收的和今天 00:10 收的（相隔 20 分钟）都会被算成
`days = 0` → 归入同一天，但它们在日历上是两天。

注释写的是「按自然日分组」，标签函数也输出「今天 / 昨天」，
但实现是滑动窗口。两者不一致。

**修法**：比较日历日期而非毫秒差。

```js
const midnight = d => new Date(d.getFullYear(), d.getMonth(), d.getDate()).getTime();
const dayDiff = (a, b) => Math.round((midnight(a) - midnight(b)) / 86400e3);
```

### P2 — 若干实现瑕疵

| 位置 | 问题 | 影响 |
|---|---|---|
| `.more` 按钮的点击分支 | `closest('.acts button')` 匹配不到 `.more`（它是 `.card__foot` 的直接子元素，不在 `.acts` 内），`if (act.dataset.act === 'more')` 是死代码 | 功能没坏（会掉到下面的 `openSheet`），但那行判断永不执行 |

| 卡片 hover 渐隐 | `-webkit-mask-image` 在 hover 时让正文底部渐隐 | hover 同时也是操作按钮出现的时机，正文变淡略抢戏。可只在 `.more` 上触发 |

## 三、产品层面：10 套主题与「轻量级」是冲突的

主题系统本身做得很好，token 架构完全撑得住。但要知道代价：

- 约 300 行 CSS token 定义
- 一个主题弹层（含分组、滚动、持久化）
- 数字键 1–9 + `t` 循环的快捷键逻辑
- **维护成本**：以后每次改卡片样式，都要在 10 套主题下各检查一遍

这是一个「一个人用一次就再也不碰」的功能。

值得诚实问一句：这 300 行换来的，是少调了哪次卡片排版的 bug？
如果答案是没有，那它就是纯负担。

**建议**：保留 2–3 套（一浅一深，加一个真正喜欢的），其余删掉或挪进注释。
核心 token 架构留着，将来想加随时能加。

## 四、结论

架构与品味都在线，值得继续做。

修复优先级：

1. **P0**：`.card::after` 加 `pointer-events:none`（一行），或直接删掉该规则
2. **P1**：`dayKey()` 改成日历日比较；`clip()` 批量读 + 搜索加 debounce
3. **P2**：其余按需
4. **产品决策**：主题从 10 套收敛到 2–3 套

### 新发现并修掉的一类问题：Swift ↔ JS 契约

评审只看了面板本身，没看它和原生之间的往返。接上原生壳之后暴露出三个**静默**错误——
都不报错，但数据会悄悄不对：

1. **卡片插两次。** `#addBtn` 调了会本地插入的 `Shiju.capture()`，
   而 `Shiju.capture()` 内部又 `bridge('capture')` 回传原生；原生落库后
   再 `pushCaptured` 推回来。结果是界面出现两张一样的卡，
   其中一张带本地假 `id`（`'n'+Date.now()`），点它的星标 / 删除全部对不上数据库。
   **修法**：确立「面板只渲染、落库归原生」，`Shiju.capture()` 不再回传。
2. **撤销收录是空操作。** 收录成功的 toast 里点「撤销」发的是 `undo`，
   原生执行 `Store.restore()` —— 即 `deleted_at = NULL`。
   但这条记录是刚插进去的，`deleted_at` 本来就是 `NULL`，于是**什么都没发生**：
   卡片从界面上消失了，下次打开面板又回来了。
   **修法**：新增 `discard` 通道做物理删除。
   这里不能改用软删——`Store.existingID()` 把软删的行也算「已存在」，
   软删之后同一句话会被去重逻辑永久挡住，用户看到的是「点了没反应」。
3. **`z` 恢复只改界面不改库。** 键盘 `z` 走的是本地 `splice`，
   没有发消息给原生，库里的 `deleted_at` 还留着。
   另外 `remove()` 的 toast 撤销没清 `state.trash`，
   撤销之后再按 `z` 会把同一条又插一遍，列表里出现两张。
   **修法**：两条路径都补发 `undo`，并在消费后立刻清空 `state.trash`。

### 测试

本机起不了无头 Chrome，所以用 jsdom 把 `panel.html` 真跑起来，
对面接一个「假原生」端模拟 SQLite 与 `pushCaptured`：

```bash
./Scripts/test-panel.sh
```

22 条断言，覆盖上面这三个问题，以及「浏览器里单独调样式时退化为纯本地插入」。

实测自检能让 6 条断言正确失败（含那张假 `id` 的孤儿卡片），说明断言不是恒真的。

`pointer-events:none` 的修法建议实机点一下按钮确认。
