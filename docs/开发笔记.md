## 它做什么（功能清单 / 规格参考）

改代码前先看一遍：下面每一条背后都有对应的实现和测试，动的时候别漏。

- 在**任意应用**里选中文字（浏览器、终端、备忘录、微信…），右下角浮出「收录」胶囊
- 点一下即存，3 秒内可撤销
- 也可以按 `⌥⌘S` 直接收录，不用先点按钮
- 菜单栏「拾」打开卡片面板：搜索、标签筛选、卡片/列表/专注三种视图
- 数据全部在本地，无账号、无云端、无遥测

## 环境要求

- macOS 13 或更高
- Swift 5.9+（本机用 Command Line Tools 即可，**不需要装 Xcode**）

## 构建

```bash
cd ~/project/Shiju
./Scripts/make-app.sh        # 编译 + 组装 dist/Shiju.app（含图标）
./Scripts/install.sh         # 装到 /Applications/拾句.app 并启动
```

`install.sh` 是日常入口——**每次重新编译后都要跑一次**，否则 /Applications 里跑的还是旧版本。

要发给别人的话，加 `--dist`（差别只在签名身份，理由见「签名与辅助功能权限」）：

```bash
./Scripts/make-app.sh --dist   # ad-hoc 签，包里不带本机证书的痕迹
./Scripts/make-dmg.sh          # → dist/Shiju-<VERSION>.dmg，1 MB 左右
```

版本号只有一个来源：仓库根目录的 **`VERSION` 文件**。`CFBundleShortVersionString`
从它读，`CFBundleVersion` 取 `git rev-list --count HEAD`。早先版本号写死在
`make-app.sh` 里，于是「打的 tag」和「包里的版本号」成了两件要手动对齐的事。

dmg 里除了 app 和 Applications 快捷方式，还有一份 **`安装说明.txt`**：
包没有 Apple 开发者签名，别人下载后双击只会看到「已损坏」，
而**那个状态下他读不到 README**——说明必须躺在盘里。

### 装好之后怎么打开

它是个菜单栏应用，**没有 Dock 图标**——启动后不会弹窗，只在菜单栏右侧出现一个「拾」字。
找不到图标时先确认它已经在跑：

```bash
pgrep -fl "Contents/MacOS/Shiju"
```

三种打开方式：

| 方式 | 操作 |
|---|---|
| 聚焦搜索 | `⌘空格` 输入「拾句」 |
| 启动台 | 找蓝色「拾」图标 |
| 访达 | `/Applications/拾句.app` |

> 包名刻意用了中文。Spotlight **只按文件名索引应用**，包名若是 `Shiju.app`，
> 搜「拾句」就搜不到，而启动台和访达显示的偏偏又都是「拾句」，两边对不上。
> macOS 上中文包名很常见（本机就有 `微信.app` / `飞书.app` / `百度网盘.app`）。

### 为什么是手工打包

本机只装了 Command Line Tools，没有 Xcode，`xcodebuild` 不可用。
SwiftPM 能编译出可执行文件，但 `.app` 的目录结构与 `Info.plist` 需要自己拼
——`LSUIElement`（菜单栏应用、无 Dock 图标）只能从那里声明。
`Scripts/make-app.sh` 做的就是这件事。

## 首次运行：必须授予辅助功能权限

这是 macOS 的强制要求，**无法绕过**。没有它，悬浮按钮不会出现，快捷键也不生效。

1. 启动「拾句」（聚焦搜索「拾句」，或从启动台）
2. 会弹出引导框，点「打开系统设置」
3. 在「隐私与安全性 → 辅助功能」中勾选「拾句」
4. 重启应用

> **注意**：应用目前是 ad-hoc 签名。每次重新编译都会改变签名指纹，
> 系统可能要求你重新授予权限。这是 macOS 的机制，不是 bug。
> 想避免的话，可以自己创建一个自签名证书并用它签名。
>
> **另外，授权是跟「路径」走的**：`/Applications/拾句.app` 和项目里的
> `dist/Shiju.app` 会被当成两个不同的应用，各要授权一次。
> 所以固定用 `install.sh` 装一份，别两个换着开。

## 图标

图标是**用代码画的**，不是一张放进仓库的图：`Scripts/make-icon.swift` 用 CoreGraphics
画一块圆角渐变底 + 一个宋体「拾」字，再由 `make-icon.sh` 交给 `sips` + `iconutil`
合成 `.icns`。改配色、改字号都只动一处，也不依赖 Xcode 或任何设计工具。

```bash
./Scripts/make-icon.sh       # → Resources/Shiju.icns（生成物，不进版本库）
```

`make-app.sh` 会在 `.icns` 缺失时自动调它。

两个踩过的坑写在这里，免得下次重画时再撞：

- **`CTLineGetBoundsWithOptions(.useOpticalBounds)` 给的框和实际落墨不一致**——
  照它居中，「拾」会偏下 27px（1024 画布上的 2.6%）。现在改成先画一遍、
  扫出真实墨迹范围、再按量出来的范围居中。换字体也不会失准。
- **位图缓冲第 0 行在图像顶部，而绘图坐标系原点在左下角**。扫像素时行号要翻一次，
  否则字会整体掉到画面底部。另外 `CGContext(data: nil)` 分配的内存不保证清零，
  探针画布必须先铺一层黑，不然会把残留数据当成墨迹。

## 测试

三套测试，都自带**变异自检**（把原来的 bug 改回去，确认断言真的会变红）——
没有这一步，测试可能是恒真的。

| 套件 | 跑在哪 | 管什么 |
|---|---|---|
| `Scripts/test-trigger.sh` | Swift 独立程序 | 触发判据：位移统计与阈值、剪贴板该不该弹、快捷键配方与登记 |
| `Scripts/test-panel.sh` | jsdom | 面板契约：消息往返、结构、CSS 规则 |
| `Scripts/test-layout.sh` | 真 WebKit（WKWebView） | 真实布局：居中、列数、换行、弹层越界 |

### 触发判据（Swift）

```bash
./Scripts/test-trigger.sh            # 完整（含自检）
./Scripts/test-trigger.sh --quick    # 只跑主用例
```

覆盖四块：

| 块 | 测什么 | 坑在哪 |
|---|---|---|
| `DragTracker` | 「按下—拖拽—松手」的位移统计与阈值 | 按事件个数判 → 快速一划只收到 1 个事件就整类漏掉；只累加事件之间的差值 → 单事件时位移恒为 0 |
| `ClipboardTrigger` | 一次剪贴板变化该不该弹按钮 | 坑全在**误触发**上（自己写的、取词往返、复制文件、密码框、按钮上已挂着同一段），而且**被挡下的那次不能污染基线** |
| `HotKeySpec` | 键码与修饰键的解析、显示、持久化 | 「只按一个字母也被接受」会把那个键从所有应用手里抢走 |
| `HotKeyCenter` | 注册失败之后那些记录还对不对 | 失败不报错、不崩溃，只是「用户改了个被占用的组合，界面上什么提示都没有」 |

`HotKeyCenter` 那一组要**真的去注册全局快捷键**（Carbon 在命令行进程里可用，已实测）。
它覆盖三处踩过的坑：失败的那次不登记 → 两个槽位共用 id → 后一个成功会冲掉前一个的
失败记录；回滚时重新装旧组合、装成功顺手把失败原因清了；注销掉失败的槽位，
失败记录没跟着走。

**环境不具备时跳过，而不是报失败**：先探测两个空闲的 `⌃⌥⌘` 组合，找不到就打印
「跳过」并说明原因——否则本机的按键占用会被误读成代码坏了。

诊断日志指到临时目录（`SHIJU_DIAG_LOG`）：这组用例会**故意**制造「注册失败」，
不重定向就会写进用户真实的那份日志里，而那份日志正是排查问题时要读的。

自检会把七个 bug 分别改回去，确认断言变红。**自检本身就是一次真实的发现**：
其中一处变异「去掉 `intersection(.deviceIndependentFlagsMask)`」改回去后断言仍然全绿
——查下来那行是**死代码**（`contains` 只查位，不关心多出来的位），
于是删掉它、把变异换成真正会改变行为的写法。留着那行，就等于留一句假装在防什么的注释。

不用 XCTest / testTarget 的原因：主 target 是 `executableTarget` 且入口在
`main.swift`，做成 testTarget 会让顶层代码在测试进程里跑起来（`app.run()` 会把测试挂住）。
所以直接用 `swiftc` 编一个独立的检查程序。注意 Swift 只允许在名为 `main.swift`
的文件里写顶层语句，脚本会先把检查文件拷成 `main.swift` 再编。

测试要编的源文件是**挑过的**（`DragTracker` / `ClipboardTrigger` / `Snippet` /
`HotKey` / `Paths` / `Diagnostics`），不碰 UI 层，所以测试进程不会建窗口、不会开数据库。
`Diagnostics` 是被 `HotKey` 拖进来的，而它能单独编，是因为日志路径已经改从
`Paths.swift` 取——原先它向 `Store.databaseURL` 借目录，方向是反的（日志要能在
数据库打开失败时照常工作），也顺带把整条 SQLite 链带进了测试的编译面。

### 面板契约（JS）

面板是 WKWebView 里的 HTML，改一行 JS 就可能悄悄破坏和原生之间的消息往返。
本机无头 Chrome 起不来（见「已知限制」），所以用 jsdom 把 `panel.html`
真跑起来，对面接一个「假原生」端模拟 SQLite 与 `pushCaptured`：

```bash
./Scripts/test-panel.sh            # 完整（含自检）
./Scripts/test-panel.sh --quick    # 只跑主用例
```

覆盖的是最容易静默出错的一类问题：卡片插两次、撤销后下次打开又回来、
按 `z` 只改界面不改库，以及**删除绕过了确认框**（T7）、
**手动记录漏传标签 / 出处 / 链接**（T8）——这几类都不会报错，
只会让用户在某天发现「东西怎么没了」或者「我填的出处去哪了」。

还有一批**纯结构 / 纯数值约束**（T10–T16），它们没有运行时症状可看，
错了只是某天发现「按钮看不见了」或者「拖宽没反应」：

| 用例 | 锁住的约束 |
|---|---|
| T10 | 新建态不该有字数统计那行，**但编辑态必须有**（别被「顺手一起删了」） |
| T11 | 关闭按钮不能挂进 `.sheet__panel`（panel 带 `overflow-y:auto`，挂进去就被裁掉） |
| T12 | 列数随宽度单调不减、有上下限、`.grid` 不能封 `max-width` |
| T13 | 标签限数、底栏不换行、按钮不被压缩也不折行、`+N` 不会被压没 |
| T14 | 标签筛选是精确匹配（正文里出现该词不算） |
| T15 | 弹层贴在锚点下方，且不越出窗口 |
| T16 | 空状态用 `min-height:100%` 撑高，且有一条收平下留白的规则 |
| T17 | 顶栏有快捷键设置入口，点了发 `settings`（且只发一条） |
| T18 | 卡片上读不到来源/徽标/时间/出处；头部容器整个不在；星标还在且是角标、有让位标记；弹窗里找得到来源（含徽标）与时间，且不再出现 id |
| T19 | 来源按**关键词**认（`Google Chrome`/`微信`/`终端`/`备忘录`/`Xcode` 都认得出）；认不出的走稳定散列色；灵感的选择器不依赖祖先 |

两个写这类断言时踩到的坑，都记在 `panel.html` 的注释里：

- **jsdom 读得到 computed style**（`getComputedStyle(...).overflow/.top/.display`），
  所以「`top` 为负」「`overflow` 不是 `auto`」都能断言。但它**读不到布局**
  （元素实际位置和尺寸，`clientWidth` 恒为 0），「居中不居中」「有没有换行」
  这类问题它验不了——那部分交给 `test-layout.sh`。
- **jsdom 和真实浏览器对 `[hidden]` 的处理是相反的**：实测 jsdom 里
  `[hidden]{display:none}` 会压过作者的 `.chip{display:inline-flex}`，
  而真实浏览器里作者样式胜出。所以「隐藏生效了吗」这件事**不能用 computed style 测**，
  T14 里换成查源码规则（`/\.chip\[hidden\]\s*\{[^}]*display\s*:\s*none/`）。
  反过来，`.chip[hidden]{display:none}` 这条规则本身在浏览器里是**必需**的
  ——没有它，`hidden` 属性设了也白设。

自检（`--selfcheck`）会把已修的 bug 逐个改回去，确认断言真的变红。
每加一条断言，都顺手加一处对应的 bug 注入，否则那条断言可能恒真。

### 主题一览那张是拼出来的

`panel-snapshot.swift` 里还有一个 `--stitch` 模式，把若干张已出好的图拼成一张：

```bash
shot --stitch --out docs/images/themes.png --cols 2 --gap 14 \
     --in a.png --in b.png --in c.png --in d.png
```

只有两个用途，但都值得：

- **主题一览**。四种主题分开放四张图，读者要自己上下滚动才能对比；
  拼在一起才一眼看出「差别只在配色」。顺带省掉三份重复体积。
- **尺寸只能试**。README 里图片按容器宽度缩放（约 1012px），
  所以**一行放几张直接决定每张能有多大**——一行 4 张每张只剩 250px，
  只能看出一团颜色；2×2 每张约 500px，卡片上的字都看得清。
  代价是图变高，所以 2×2 是「看得清」和「别太高」之间试出来的那个点。

三个实现细节：

- **背景留透明**。README 在 GitHub 的浅色和深色两种页面下都会被渲染，
  填一个固定底色的话总有一种模式看着是错的。
- **行号要翻一次**。CG 的原点在左下角，图是自上而下排的，
  多行拼出来不翻行号整排顺序是倒的（和画图标那次踩的是同一个坑）。
- **不缩放**。调用方出的图尺寸本来就一样，缩放只会引入重采样误差——
  `sips -Z` 对小图甚至可能把文件**变大**（实测 1600px 那次从 410K 涨到 719K）。

切主题的入口在 `Tests/snapshot-themes.js`。那里有两个不能省的细节：
`applyTheme` 会写 `localStorage`，所以每次都要先 `SNAP.reset()`（否则第二次跑的图和第一次不一样）；
以及**第二个参数必须显式传 `false`**——`applyTheme(key, notify)` 里写的是
`if (notify !== false) bridge('setTheme', …)`，不传就是 `undefined`，
`undefined !== false` 成立，它会去调 `bridge`，而截图工具里**没有注册那个 messageHandler**，
于是整个注入脚本抛异常，出来的是一张「数据没进去」的空图。

三个实现上的坑：

- **必须 `orderFront`**。不在窗口层级里的 WKWebView 不会真正排版，
  截出来是一张空白图。窗口挪到 `(-40000, -40000)` 就够，不打扰用户。
- **截图前要冻住动画**。卡片是 `animation: cardIn .3s ... both` 从 `opacity:0`
  淡入的，而离屏窗口不推进动画 → 卡片永远停在 `opacity:0`，截出来
  「顶栏正常、卡片区一片空白」，很容易被误读成渲染坏了。工具会注入一条
  `animation:none !important` ——面板自己就有这条降级规则
  （`@media (prefers-reduced-motion: reduce)`），等于手动扮演一次「用户开了减弱动态效果」。
- **无值开关要单独解析**。早先的参数解析是「每个参数都强行取下一个当值」，
  放在最后的 `--probe` 取不到值就直接跳出循环，开关静默失效，
  截图模式下跑完还报成功。

`--probe` 不截图，只把 JS 的返回值打到 stdout——于是「居中差了几像素」
可以量出来而不是估出来。`Tests/layout-probe.js` 就用它跑断言，
**跑四档宽度：1200 / 1000 / 760 / 520**。最后那档是窗口能拖到的最窄值
（`PanelWindow` 里 `minSize` 就是 520），专门用来抓「顶栏被挤扁」这类
只在最窄处出现的问题。当前覆盖：

- 空状态：水平/垂直居中（各视口偏差 0px）、没撑出滚动条
- 列数：每列不窄于 268px、各列等宽、**且已经取到最多**（再加一列就低于下限）
- 底栏：标签与按钮在同一行、高度只有一行、按钮没被压没、没溢出卡片
- 底栏：多标签收成 `+N`、超长标签被省略号截断
- 顶栏：设置入口点得到、是方的、在主题按钮左边、同一行、按钮没被压得比内容还窄
- 弹层：贴在锚点下方、不越出窗口、主题弹层没有底部文案
- 标签入口：有标签才可见，且 `hidden` 时真的不占位
- 卡片：没有来源徽标/来源名/时间/出处；**正文紧贴内容盒上沿**（没留下空档）；
  星标是卡片的直接子元素、落在卡片内、**且不压到正文上**（网格与列表各一条）
- 详情弹窗的来源徽标：**真的画出了颜色**——读 `backgroundColor` 算通道极差
  （灰底极差≈0）。jsdom 解析不了 `hsl(var(--badge-h) …)`，这条只有真渲染才验得了

断言尽量贴着**需求**而不是实现写：列数那条断言的是「每列不窄于 268，
且再加一列就低于 268」，而不是「`colCount` 返回 4」——公式以后换成别的写法，
这条仍然该成立。

「同一行」也不能拿 `top` 相等来判：底栏是 `align-items:flex-end`，
标签（16px）和按钮（22px）底边对齐、高度不同，中心和 `top` 本来就差几像素。
真正该成立的是**所有子元素的垂直区间有公共重叠**——一旦换行，
第二行会整个落到第一行下方，重叠就没了。

### 跑之前先 `node --check`

探针是一个大 IIFE，里面几十个 `const`。不小心重名（比如别处已经有个 `squeezed`）
会让**整个脚本解析失败**，而 `evaluateJavaScript` 只会回报
「A JavaScript exception occurred」——一个字的细节都没有，极难定位。
所以脚本开头先对 fixtures 和探针各做一次 `node --check`，
再把两个文件 `cat` 到一起检查一遍（它们是拼在一起注入的，跨文件重名同样致命）。
一秒的代价换一条能指出行号的报错。

自检会把七处改回去：空状态撑高换回旧公式、去掉收平下留白那条规则、
去掉 `.chip[hidden]`、顶栏让位改回旧写法（**这条必须在 520px 下跑**，
1200px 空间富余，怎么改都不会挤）、卡片头部又长回来、星标不给角标让位、
窄窗下列表行不给角标让位（**这条也只在 520px 下会红**——宽一点右侧还有
84px 的操作槽，角标压不到正文）。`.chip[hidden]` 那处特别值得留着——
它当初是 review 发现的，测试没抓到；现在在真 WebKit 里跑，
`hidden` 属性设了但不生效这件事能被直接抓住。

## 面板 ↔ 原生 的消息契约

面板只负责渲染，**落库一律交给原生**——这样卡片上的 `id` 永远是数据库里的真 `id`，
后面的星标 / 删除 / 编辑才对得上。约定如下：

| 方向 | 名称 | 含义 |
|---|---|---|
| JS → 原生 | `capture` | 请求收录一段新文本，原生落库后回调 `Shiju.capture` 推回真卡片。面板「＋ 记录」走这条时会一起带 `tags` / `title` / `url`；空串由原生归一成 `NULL`，否则卡片元信息里会出现一栏空白 |
| JS → 原生 | `discard` | 撤销**刚收录**的那条：物理删除（用软删会被去重逻辑永久挡住，同一句话再也收不进来） |
| JS → 原生 | `delete` | 移入回收站（软删） |
| JS → 原生 | `undo` | 从回收站恢复 |
| JS → 原生 | `star` / `edit` / `copy` / `setTheme` | 星标 / 改正文与标签 / 复制到剪贴板 / 记住主题 |
| JS → 原生 | `settings` | 顶栏 ⚙ 被点了，请原生开快捷键设置窗口 |
| JS → 原生 | `startDrag` | 顶栏空白处按下，请原生把窗口跟着鼠标挪（见「窗口拖动」） |
| 原生 → JS | `hydrate` | 灌入全量数据（面板不持有真相，每次打开重新灌） |
| 原生 → JS | `capture` | 收录成功，把真卡片插到最前（含入场动画与 3 秒撤销） |
| 原生 → JS | `setTheme` | 应用上次记住的主题 |

`discard` 与 `delete` 是两件事：前者是「这次收录没发生过」（硬删），
后者是「移入回收站」（软删、7 天内可恢复）。混用会导致撤销之后同一句话再也收不进来。

### 删除一定要过确认框

面板没有回收站入口，所以「删除」在用户看来就是**永久没了**（库里的软删标记
只是给「撤销」留的 4 秒窗口，过了就找不回来）。一个手滑的 `Delete` 键不该有这种后果，
所以两条删除路径（卡片上的按钮、详情里的删除）都收敛到同一个 `<dialog id="confirm">`：

- 文案里带上那句话本身，否则用户不知道自己在删哪一条；
- 「取消」和点遮罩都只是关掉框，**并且把 `pendingDelete` 清空**——
  不清的话下次点删除会拿一个已经过期的 id 去删；
- 确认键只接受点击，**不绑 `↵`**。删除不可逆，不该被一个顺手的回车带走。

### 手动记录与编辑共用弹窗

「＋ 记录」以前走 `window.prompt`：`WKWebView` 默认不实现它（要靠 `WKUIDelegate` 补），
而且只能收一行字。现在它和「编辑」共用同一个 `<dialog>`，靠 `sheetMode`
（`view` / `edit` / `new`）切换三种形态，`new` 多出「出处 / 链接」两个选填字段。

`saveNew()` 同样**只发消息、不本地插入**——原生落库后回调 `Shiju.capture`
把真卡片推回来，卡片上的 `id` 才是库里的真 `id`。
落库后再补一次本地插入会得到一张带本地假 `id` 的「孤儿卡片」，
它的星标和删除都对不上库，这正是契约测试 T1 盯着的那条。

**新建态比编辑态更素**：文本框下面那行「N 字 · N 行 + `⌘↵` 保存 · `Esc` 取消」
只在编辑态出现。手动记录刚打开时那行报的是「0 字 · 1 行」——没有信息量，
却占掉第一眼的注意力。底栏也只剩两个按钮（原来左边还有一句
「手动记录 · 不填出处也没关系」，而表单里每个字段都已经写着「（可不填）」）。
编辑态两样都保留：那里字数会变，是有效信息。

### 详情弹窗的结构：dialog 是容器，卡片是内层

关闭按钮要在卡片的**右上角之外**，这带来一个结构问题：
`<dialog>` 的 UA 样式带 `overflow: auto`，**会把溢出到卡片外的按钮直接裁掉**。
而 `overflow` 又不能简单地改成 `visible`——长句子时内容会直接溢出到屏幕外，
底部按钮就点不到了。

所以拆成两层：

```html
<dialog class="sheet" id="sheet">          <!-- 透明定位容器：overflow:visible -->
  <button class="sheet__close" id="sheetClose">…</button>   <!-- 悬在卡片上沿之外 -->
  <div class="sheet__panel">                <!-- 卡片外观 + 滚动 + 圆角裁剪 -->
    <div class="sheet__body" id="sheetBody"></div>
    <div class="sheet__foot" id="sheetFoot"></div>
  </div>
</dialog>
```

- `.sheet`：`border:0; background:transparent; box-shadow:none; overflow:visible`，
  只负责定位；
- `.sheet__panel`：`border` / `border-radius` / `background` / `box-shadow` 都在这，
  加 `max-height: calc(100vh - 120px); overflow-y:auto` 承担滚动，
  `overflow` 非 `visible` 顺带触发圆角裁剪；
- `.sheet__close`：`position:absolute; top:-34px; right:0`。

**按钮挂在 dialog 下、而不是 panel 里**，这点不能改：panel 为了能滚动带
`overflow-y:auto`，按钮挂进去会被一起裁掉，表现就是「详情弹窗看不见关闭按钮」。
契约测试 T11 专门锁这条结构约束（按钮不在 panel 内、dialog 的 `overflow` 不是
`auto`、`top` 是负值）。

`right:0` 而不是 `right:-26px`：卡片宽度是 `min(580px, 92vw)`，
飘到卡片右边的按钮在窄屏上会顶到视口边缘。

## 卡片上只留句子，元信息进弹窗

卡片头部原来有两行：「来源徽标 + 来源名 + 时间」一行，出处标题一行。用户连着两条反馈：

> 每个卡片上的不需要显示来源和 icon 还有时间，这些都放在弹窗里面显示

> 卡片上的出处先删除

道理很直白：卡片是拿来**扫读**的。头上每多一行，正文就往后挪一行，
一屏就少一排卡片。但「这句哪儿来的」不能丢，只是不必天天摆在眼前——
挪进详情弹窗按需看。

改完之后的分布：

| 信息 | 卡片 | 详情弹窗 |
|---|---|---|
| 来源徽标（icon） | — | ✅「来源」行里，和名字并排 |
| 来源名（Safari / 微信…） | — | ✅ |
| 时间 | — | ✅「时间」行（相对时间 + 绝对时间） |
| 出处标题 | — | ✅ |
| 标签 / 字数 | ✅ | ✅ |
| 星标 | ✅ 右上角的角标（见下） | ✅ |
| 记录的 id | — | **去掉**（用户原话：「弹窗里面最底下不需要显示 id」） |

列表视图的 meta 行保留了「出处 · 字数 · 标签」——它是另一种视图，
行宽富余、本来就是一行的摘要。要一起撤的话，改 `metaTitle` 那一处即可。

### 来源徽标只有一份映射表

徽标要同时出现在弹窗的「来源」行里，所以把 `sourceOf(x)` 抽了出来
（`{ name, badge, html }`）。抽的原因不是洁癖：徽标字母的映射表
（`Safari:'S'`、`WeChat:'微'`、`Terminal:'$_'`…）原先写在卡片渲染函数里，
弹窗要用就得再抄一份，改一处忘一处。现在卡片只用它的 `name`
（用来把「来源名」从标签列表里剔掉）。

顺带统一了一处口径：灵感类记录在弹窗里的「来源」原本写「手动记录」，
现在跟卡片一样写「灵感」——同一个概念两套措辞是 bug 的温床。

### 「来源 icon 是不是可以有点颜色」——根因是它压根没上色

用户的第三条反馈是：

> 卡片详情的来源 icon 是不是可以有点颜色

查下来不是配色不够艳，而是**徽标根本没上色**。`source_app` 存的是
`NSRunningApplication.localizedName`（见 `Capture.swift`），实测是
**「Google Chrome」「微信」「终端」「备忘录」「Xcode」**；而面板的映射表键
写的是 `{ Chrome:'Chrome', WeChat:'微信', Notes:'备忘录', … }` 这种短名，
于是**除了 Safari 之外一个都对不上**，全部落到 `var(--color-text-3)` 的灰底兜底。
翻了下真实库：9 条 `Google Chrome` + 1 条 `微信`，两条都是灰的。

改成按**关键词**认（`names.some(n => lower.includes(n))`），
和 `Store.swift` 里按 `LIKE '%chrome%'` 认浏览器/终端是同一套口径——
那边决定「算哪种类型」，这边决定「画什么徽标」，两处必须一致。

认不出来的应用（比如 `Zed`）也不再是灰的，而是按名字散列出一个**稳定色相**：

```js
function hueOf(name){
  let h = 7;
  for (const ch of String(name)) h = (h * 31 + ch.codePointAt(0)) % 360;
  return h;
}
// 色相写进 CSS 变量，具体长相留在样式里
`<span class="badge" style="--badge-h:${hueOf(name)}">…`
```

颜色分三种情形，全部由 CSS 决定长相，JS 只负责标出「是哪一种」：

| 情形 | 标记 | 底色 |
|---|---|---|
| 认得出的应用 | `data-brand="chrome"` … | `--brand-*`（品牌色，不随主题变） |
| 灵感（自己写的，不是采集的） | `data-brand="idea"` | `--color-accent-soft` + `--color-on-accent-soft` |
| 认不出的应用 | `style="--badge-h:N"` | `hsl(N 42% 46%)` |

两个坑：

- **灵感那条选择器必须挂在徽标自己身上。** 早先写的是
  `[data-kind="idea"] .badge`，靠卡片的 `data-kind` 祖先上色；
  而**详情弹窗里没有那个祖先**，这条规则在弹窗里静默失效，退回灰底。
  现在写成 `.badge[data-brand="idea"]`。
- **断言要带上 `\s*\{`。** 注释里为了说明「不要这么写」会把旧选择器原文抄一遍，
  只匹配选择器本身的话，注释也会被当成规则——这条一开始就是这么误报的。

布局探针里还有一条**真渲染**的判据：读 `getComputedStyle(badge).backgroundColor`，
算三个通道的极差（灰底的极差接近 0）。jsdom 读不出
`hsl(var(--badge-h) …)` 解析成什么颜色，WebKit 可以——
「有点颜色」这件事最终是画出来的，不能只验规则写没写。

### 卡片头部整块撤掉，星标改成右上角的角标

出处也撤掉之后，`.card__head` / `.head__row` / `.card__title` 整套都成了死代码，
一并删掉。撤容器不能只把里面的内容清空：容器自带的 `padding-bottom`
会在正文上方留下一段没有来由的空白。布局探针量这个：
**正文 top 减去卡片上沿，再减去内边距和边框，必须是 0**。
第一版忘了算那 1px 边框，量出「空档 1px」，还以为是真 bug。

星标不能跟着撤——它是用户自己按下的状态，藏起来等于丢了反馈。但它也不能占一行：
占一行的话，有星标的卡片正文会比旁边低 23px，网格里一眼就看出来参差。
所以做成**绝对定位的角标**：

```css
.card__star{ position:absolute; top:9px; right:11px; pointer-events:none; }
```

角标不参与布局，于是要**手动给正文让位**——正文是两端对齐的，
会一直写到内容盒右沿，不让位就和 ★ 叠在一起：

```css
.card{ --star-w: 0px;
       padding: var(--pad-card-y) calc(var(--pad-card-x) + var(--star-w)) var(--pad-card-b); }
.card[data-star="1"]{ --star-w: 16px; }
```

`--pad-card` 原来是三值简写（`14px 16px 13px`），**必须拆成三个变量**：
`calc(var(--pad-card) + 16px)` 会展开成「calc(14px 16px 13px + 16px)」，
是无效值，整条声明被静默丢掉——表现就是角标压到了字上，而且不报任何错。

三处例外：

- 列表行右侧本来就有 84px 的操作槽，角标落在槽里，不用再让；
  但 **≤720px 会把槽撤掉**（`padding-right` 变 16px），所以窄窗下要补回 30px。
- 专注态的卡片没有右边距（`padding: 0 8px`），正文一直写到边上，
  所以角标挪到卡片**上方**的右上角（`top:-22px`），不跟正文抢那条边。
- 断言写成「两个盒子不相交」而不是「星标在正文右边」：
  专注态是上下分开的，只判左右会误报。

### 列表视图里那个「没有前文的顿号」

列表视图的 meta 行原本是 `[徽标][来源名] [出处] · [标签] [时间]`，
撤掉首尾两项后只剩出处、字数、标签。但「字数」前面那个分隔点是 CSS 的
`::before` 无条件画的：

```css
.grid.list .card__meta .count::before{ content:"·"; }   /* 旧 */
```

于是「灵感」这类**没有出处标题、直接以字数打头**的卡片会渲染出「· 12 字」——
一个没有前文的顿号。改成只在它前面真有东西时才画：

```css
.grid.list .card__meta .count:not(:first-child)::before{ content:"·"; }
```

（`title + count` 那种情况下 count 是第二个子元素，点照画；
只有 count 一个的时候它是 `:first-child`，点不画。）

## 面板宽度是个变量

面板窗口可以拖到任意宽度（默认 1020，1 列到 6 列都能用），所以布局里凡是
「按宽度分档」的东西都不该写死。踩过的三处：

### 一行放几列：连续算，别写断点

原来的 `colCount()` 是 `w >= 1080 ? 4 : w >= 760 ? 3 : w >= 470 ? 2 : 1`，
而且 `.grid` 上还有 `max-width: 1160px`。两件事叠在一起的结果是：
**面板拖到 1160 以上，列数就再也不涨了**——用户看到的就是「拖了没反应」。

现在改成按「每列至少 `MIN_COL_W`」连续计算：

```js
const MIN_COL_W = 268, MAX_COLS = 6, GRID_GAP = 12;
function colCount(width){
  const w = Math.max(Number(width) || 0, 320);
  return Math.max(1, Math.min(MAX_COLS, Math.floor((w + GRID_GAP) / (MIN_COL_W + GRID_GAP))));
}
```

断点会在两档之间留下一段「拖了但没反应」的区间；连续公式没有这个问题。
`GRID_GAP` 与 CSS 的 `--gap-grid` 同源，改一处要改两处。
`.grid` 的 `max-width` 也一并去掉了——列数算得再对，宽度封顶就白算。

### 标签多了不能把底栏挤坏

卡片底栏一行里同时有「标签」和「星标 / 复制 / 删除」。窄卡片（4 列时约 280px）
根本放不下三个按钮加一堆标签，原来的表现是标签换行、按钮文字也被压得折行。

四条一起才管住：

| 做法 | 防的是 |
|---|---|
| 标签限数，其余折成 `+N` | 标签无限增长 |
| `.foot__tags` 不 `wrap` | 换行把按钮顶到第二行 |
| `.tag` 截断 + `title` 放全名 | 单个长标签把底栏撑开 |
| `.acts` `flex:0 0 auto` + `white-space:nowrap` | 按钮被压缩、文字折行 |

限几个跟着卡片宽度走（`lastCols` 是 render 刚算出来的列数）：
1 列露 3 个、3 列露 2 个、4 列以上只露 1 个；列表视图固定 3 个。
宽卡片不浪费位置，窄卡片不挤。

### 顶栏：空间不够时该压搜索框，不该压按钮

顶栏有「搜索框 / 卡片·列表·专注 / 主题 / ＋记录」几样东西，`minSize` 是 520px。
拖到最窄时会挤——而**先被挤坏的是按钮**：

| 视口 | 搜索框 | 视图切换 | 主题 | ＋记录 |
|---|---|---|---|---|
| 520（修复前） | 199 | 97 | **55** | **55** |
| 520（修复后） | 96 | 126 | 65 | 65 |

「＋ 记录」只剩 55px 时文字会折行（按钮高度写死 28px，于是被裁掉半行）。
根因是搜索框里 `<input>` 的固有宽度（默认 `size≈20` 字符 ≈ 190px）顶着不让缩，
flex 只好把压力转嫁给右边的按钮。

```css
.search{ min-width: 0; }                       /* 允许它缩到内容宽度以下 */
@media (max-width:760px){
  /* basis 给 0 才会在空间不足时真的让位，min-width 保证不让到没法输入 */
  .search{ width:auto; flex:1 1 0; min-width:96px; max-width:200px; }
}
```

**搜索框窄一点无所谓，按钮缺字就是坏了。**

这条只有拖到最窄才暴露，所以 `test-layout.sh` 的宽度档里专门加了 **520px**
（就是 `minSize`），并配一条断言：按钮不能被压得比它的「固有宽度」还窄。
量固有宽度的办法是克隆一份、脱离 flex 按 `max-content` 排——

```js
const naturalWidth = el => {
  const c = el.cloneNode(true);
  c.style.cssText = 'position:absolute; left:-9999px; top:0; width:max-content;';
  document.body.appendChild(c);
  const w = c.getBoundingClientRect().width;
  c.remove();
  return w;
};
```

不能用 `scrollWidth > clientWidth` 判「文字被裁」：按钮是 flex 容器、
`overflow: visible`，被压时文字是**换行**而不是溢出，那个指标照样说 ok。

### 顶栏弹层：位置现算，别写死 `right`

主题弹层的锚点（主题按钮）右边还有「＋ 记录」，所以它**不在窗口最右边**。
原来写死 `right: 14px`，弹层贴的是窗口边，跟按钮没关系。现在打开时按锚点算：

```js
function popoverPos(anchor, popW, viewW, margin, gapY){
  return {
    left: Math.max(margin, Math.min(anchor.left, viewW - popW - margin)),
    top: anchor.bottom + gapY,
  };
}
```

贴锚点左沿，但左右都不越出窗口（窄面板时按钮可能已经很靠右）。
抽成纯函数是为了能单测——真实坐标要靠布局算，jsdom 给不出来。
窗口 resize 时也要重算，锚点跟着顶栏一起动。

## 标签：从「点一下搜」到「按标签筛」

卡片上的标签点一下会填进搜索框，但那是**全文模糊匹配**——正文里出现同一个词
也会命中。想要「只看着这个标签的东西」，需要的是精确筛选，所以筛选栏里多了一个
「标签」入口（库里一个标签都没有时整个藏起来）：

- 列出所有标签 + 出现次数，按次数降序（同次数按拼音，保证顺序稳定）；
- 选中后入口自己变成「标签名 + 命中条数」，再点开可以换或清除；
- 筛选条件与搜索框是 **AND** 关系，和「星标 / 灵感 / 网页 / 终端」那几个 chip 也是 AND；
- `Shiju.capture` 和 `hydrate` 都会把它清掉——刚收录的东西必须看得见。

实现上有个坑：标签列表复用了 `.theme` 那套外观，而 `applyTheme` 里原本是
`$$('.theme')` 全量刷 `aria-pressed`，会把标签行的选中态一起刷掉。
选择器必须限定成 `#themeList .theme`。同理 `render()` 里的 `$$('.chip')`
要改成 `$$('.chip[data-filter]')`，否则标签入口的计数会被写成「终端」的条数。

## 空状态要真的居中

旧版是 `.empty{ padding:80px 0; text-align:center }`——水平靠 `text-align` 勉强算居中，
垂直方向只是往下推 80px。而 `.grid` 是 flex 容器、`.content` 是 `overflow:auto`，
**不主动撑高的话容器只有一行文字那么高**，垂直居中无从谈起。现在空状态时给
`.grid` 挂 `is-empty`，用 flex 双向居中 + 撑满内容区：

```css
.content:has(> .grid.is-empty){ padding-bottom: 4px; }
.grid.is-empty{
  display:flex; align-items:center; justify-content:center;
  min-height: 100%;
}
```

`min-height` 一开始写的是 `100vh - 顶栏 - 筛选栏 - 常数`，那个常数（76px）
得同时盯着筛选栏高度和 `.content` 的上下内边距，改一处忘一处就会偏。
**实测偏上 18px**——而且因为 jsdom 读不到布局，这个偏差一直没被测出来。

改成 `min-height:100%` 之后不含任何需要同步的常数：百分比是相对 `.content`
的内容盒算的，而 `.content` 是 flex 项、高度确定，所以这个百分比有确定的值。

还剩一处：`.content` 的内边距上下不对称（`4px` / `26px`，后者是给「滚到底」
留的呼吸位），只给 `100%` 仍会偏上 11px。而空状态压根没有滚动，
用 `:has()` 把那 26px 收平即可。改完在 1100×760 / 900×420 / 1440×900
三种视口下偏差都是 **0px**。

有数据时必须摘掉 `is-empty`，否则卡片会被 flex 居中排成一竖列。

这个偏差现在是 `Scripts/test-layout.sh` 在真 WebKit 里量的，改回旧写法会变红。

## 面板的窗口：留白与拖动

面板窗口用了 `fullSizeContentView`，内容铺满整个窗口，**标题栏（连同红绿灯）
是浮在内容之上的**。由此带来两件事：

### 顶部必须留白，否则 logo 被红绿灯压住

HTML 里 `.topbar` 的 `padding-top` 是 `var(--titlebar-h)`：

```css
:root{ --titlebar-h: 32px; }              /* 兜底 */
.topbar{ padding: var(--titlebar-h) 16px 0; height: var(--h-topbar-total); }
```

用 `padding` 而不是 `margin`，是为了让顶栏的玻璃底一直铺到窗口最顶端——
否则标题栏那一条会和下面的顶栏分成两种材质，很割裂。

真实高度由原生量出来再注入，**不硬编码**：

```swift
let h = window.frame.height - window.contentLayoutRect.height
webView.evaluateJavaScript("document.documentElement.style.setProperty('--titlebar-h','\(Int(h))px');")
```

本机实测是 **32pt**，不是常见的 28——这个值会随系统版本、工具栏、无障碍设置变，
量出来最稳。兜底值取 32（宁大勿小：多留一点只是空一行，留少了就是内容被按钮压住）。

### 拖动：`-webkit-app-region` 在这里是**无效**的

HTML 里原本写着 `-webkit-app-region: drag`——那是 **Electron 的私有属性，
WKWebView 不实现它**。写上只会让人以为「拖动已经支持了」，然后对着拖不动的窗口
去找别的原因。所以拖动必须自己接，分两条路：

| 区域 | 做法 |
|---|---|
| 标题栏那一条（顶栏的 padding 区） | 原生 `TitlebarDragView` 盖一层透明视图，`mouseDown` → `window.performDrag(with:)` |
| 顶栏的空白处（`.spacer`、logo） | JS 在 `mousedown` 时发 `startDrag`，原生合成一个 `mouseDown` 再 `performDrag` |

两条都要：原生那层只盖住标题栏，够不到顶栏中间那片空白；
而 JS 那条路走不到标题栏（那一条被原生视图接管了）。

JS 侧要放过控件，否则按钮点不动（等价于 Electron 的 `no-drag`）：

```js
if (e.target.closest('button, input, label, a')) return;
```

原生侧**不要用 `NSApp.currentEvent`**：JS 消息是异步送到主线程的，
等它到达时当前事件可能已经变成 `leftMouseDragged` 甚至 `nil`，
`performDrag` 就会拿到错的起点（表现为「一拖就跳」或完全不动）。
按「此刻鼠标在哪」自己合成事件，起点必然正确：

```swift
let local = window.convertPoint(fromScreen: NSEvent.mouseLocation)
let event = NSEvent.mouseEvent(with: .leftMouseDown, location: local, /* … */)
window.performDrag(with: event)
```

## 快捷键：可配置，而且注册不上要说出来

两个快捷键，都能改。**入口有两个**：

- **面板顶栏的 ⚙**（主入口）
- 右键点菜单栏「拾」→「快捷键设置…」

| 快捷键 | 默认值 | 作用 |
|---|---|---|
| 打开面板 | `⌥⌘S` | 把卡片面板叫出来 |
| 收录选中文字 | `⌥⌘C` | 不点悬浮按钮，直接收录当前选区 |

### 入口为什么从菜单栏挪到面板顶栏

最初只挂在右键菜单里。用户反馈「没看到设置入口」——藏在一个**要右键才出现、
平时根本不会去点**的地方，等于没有。面板才是天天看得见的地方。

顶栏加一个纯图标按钮，代价是它会跟搜索框抢宽度。所以：

- 图标画的是**滑杆**不是齿轮。齿轮在 15px 下缩成一圈辐条、看着像太阳，
  而它右边紧挨着的就是主题按钮，很容易被误读成亮度调节。滑杆是通用的
  「偏好设置」符号，两行也正好对应窗口里的两个快捷键。
- 按钮 `width:28px` 写死，跟 `.btn` 的 `height:28px` 对齐——不写死宽度的话
  一排按钮的基线会因为内边距不同而歪。

点一下方框进入录制态，按下组合即记下。`Delete` 清空（表示不要这个快捷键），
`Esc` 取消录制。**至少要有一个 ⌘ / ⌥ / ⌃**——只按一个字母当全局快捷键会把那个键
从**所有**应用手里抢走，用户录完之后连打字都不正常了，而且不会立刻联想到是这里干的。
所以 `⇧A` 这种不合法（那本来就是个大写字母），会被蜂鸣拒绝、但不退出录制态。

「打开面板」刻意**不检查辅助功能权限**：面板本身只是读数据库，不需要任何授权。
权限出问题时，用户至少还能靠它把库打开看看。

用 Carbon 的 `RegisterEventHotKey` 而不是 `NSEvent` 键盘监听：后者需要额外的
**「输入监控」权限**（和辅助功能是两个独立授权），没授予时只是静默不工作。

### 注册不上必须有反馈

这类功能最常见的坑是「用户设了个被系统或其他应用占用的组合，界面上什么提示都没有」，
用户只会以为「拾句的快捷键坏了」。所以：

- 注册失败时**把旧的装回去**，并把失败原因显示在设置窗口里（`⚠︎ ⌥⌘S 已被系统或其他应用占用…`）。
  不装回去的话，用户改了个冲突的组合，结果是新旧两个都没了。
- 失败原因**挂在登记项上**，不是一个全局的「最近失败」。`applyHotKeys` 会依次处理
  两个快捷键，只留一个字段的话，后一个注册成功会把前一个的失败提示冲掉——
  而用户刚设错的偏偏是前一个。
- **注册失败也会登记下来**（`ref` 为 nil、`failure` 记着原因）。这样它是一个
  「存在但没绑上」的槽位：用户换一个好组合时走 `update` 就地重试，不必重新分配 id。
  早先失败就 `return nil` 且不登记，而 `nextID` 又没往前走——两个槽位会共用同一个 id，
  后一个注册成功就把前一个的失败记录清掉了。
- 回滚那次注册成功**不能**把失败原因清掉，否则提示被自己冲掉。

### 录制期间必须把已注册的摘掉

否则用户按到「当前正占用」的那个组合时，Carbon 会在系统层把它吃掉，
录制控件根本收不到 `keyDown`——表现是「想改快捷键，结果一按就触发了旧功能，而且改不了」。

配套的两个顺序问题（都会让提示静默消失）：

- **`endRecording()` 必须在 `onChange` 之前**。挂起期间 `update` 走的是「只存组合、
  不真注册」那条分支，于是冲突根本不会被尝试、`failure` 永远是 nil。
  先恢复注册，`onChange` 里的注册尝试才是真的。
- **关窗口时要把录制态复位**（`cancelRecording()`）。`recording` 是控件状态，
  窗口关掉不会自己复位；不复位的话下次打开窗口点那个框会被
  `guard !recording` 直接挡掉，录制器整个变砖，而且看不出任何原因。

## 复制也是一次收录意图（剪贴板触发）

只认拖拽和双击是不够的。用户的复制方式有三种，后两种**不产生任何拖拽事件**：

| 方式 | 有拖拽事件？ |
|---|---|
| 划选一段 | 有 |
| **`⌘C`** | 没有 |
| **右键菜单「复制」** | 没有 |

早先只认拖拽，于是「我明明复制了，按钮没出来」。现在多一条剪贴板路径，
它还有第二个好处：**不依赖 AX 取词**，所以在微信这类自绘界面、取词拿不到文本的
应用里也能工作。

判据（`ClipboardTrigger`，纯逻辑、可单测）按这个顺序挡：

| 顺序 | 挡什么 | 为什么 |
|---|---|---|
| 1 | 是自己刚写的 | 点卡片上的「复制」不该把悬浮按钮叫出来 |
| 2 | 系统处于安全输入 | 密码框 |
| 3 | 前台应用在忽略名单里 | 见下 |
| 4 | 复制的是文件而不是文本 | 那不是「句子」 |
| 5 | 去掉空白后是空的 | |
| 6 | 和上次认过的一样 | 同一段复制两遍 |
| 7 | 按钮上已经挂着同一段 | 先划选、再 `⌘C`，不该弹第二次 |

**第 6 条的基线只在最后一步更新。** 中途 `return` 时如果顺手把基线改了，
一次误触发就会把它带偏，之后所有正常的复制都会被当成「和上次一样」而**静默漏掉**。
测试里有一条专门锁这个。

### 剪贴板没有事件通知

`NSPasteboard` 不发通知，只能轮询 `changeCount`（0.4s 一次）。这跟上面
「触发靠事件，不靠轮询」不矛盾：那边有鼠标事件可用，这边没有。
定时器挂在 `.common` 模式上，否则**菜单一打开轮询就停了**，
用户「在右键菜单里选复制」反而抓不到。

### 取词的往返要消化掉

`SelectedTextKit` 走 `⌘C` 通道时是「备份剪贴板 → 模拟 `⌘C` → 读 → 还原」，
剪贴板会绕一圈。不处理的话**每次取词都会顺手多弹一次按钮**，而且弹出来的可能是
用户上一次复制的内容。做法是取词前后 `pause()` / `resume()`，`resume` 里把现状
重新记为基线，整段往返就此消化掉。

### 拾句自己也在忽略名单里

少了这一条，在面板里**拖窗口**（面板是特意做成可拖的）会被当成一次
2744pt 的划选，在卡片里选中文字想复制也一样——每次都白跑一趟 AX 取词，
日志里刷满「检测到拖拽选择结束 / 放弃取词」，真选中卡片文字时还会在自己面板上
弹出自己的按钮。这是看真实日志发现的：噪声占了大半，排查真问题时非常碍事。

## 三个关键技术点

### 1. 悬浮窗绝不抢焦点

`PopButtonWindow` 用无边框普通 `NSWindow`，重写两个方法返回 `false`：

```swift
override var canBecomeKey: Bool { false }
override var canBecomeMain: Bool { false }
```

原应用不失焦，选区就不会被系统清除。**这是整个方案能成立的前提**——
一旦抢了焦点，按钮点下去就抓不到内容了。

### 2. 触发靠事件，不靠轮询

macOS 没有「用户选中了文字」的系统通知。这里监听全局鼠标事件，走三条路径：

| 路径 | 判据 | 覆盖的操作 |
|---|---|---|
| 拖拽划过 | 从按下到松手累计位移 ≥ 4pt | 划选一段 |
| 连击 | `clickCount ≥ 2` | 双击选词、三击选行 |
| 剪贴板 | `changeCount` 变了且过了判据 | `⌘C`、右键菜单「复制」（见上一节） |

两个细节是踩出来的：

- **判据必须是「位移距离」，不能是「事件个数」。** 早先要求
  `leftMouseDragged` 收到 ≥2 个事件，但快速一划时系统会合并鼠标事件，
  可能只收到 1 个——于是漏掉一整类「划得很快」的选择。
- **位移的起点必须取 `leftMouseDown` 的位置。** 只靠拖拽事件之间的差值，
  在「只收到 1 个事件」时压根没有参照点，算出来是 0，等于没修。
  （这条是看诊断日志发现的：`累计位移只有 0pt`。）
- **双击选词不产生任何拖拽事件**，只看拖拽的话，最常用的「双击选个词」
  反而永远不弹按钮。所以要单独看 `clickCount`。

第三条路径是唯一需要轮询的，原因和取舍见上一节。

4pt 这个阈值是刻意选的：手抖的单击通常只挪 1–2pt，划选一个字至少十几个点，
中间有足够宽的区分带。误触不用担心——双击标题栏、双击文件图标也会走到这里，
但取词那一步拿不到文本，按钮自然不弹。

### 3. 按钮会自己收起来

- 滚动累计超过 80pt → 收起（你在继续往下读）
- 鼠标移出按钮外扩 40pt 的区域 → 收起（你已经走开了）
- 静置 4s → 淡出
- 例外：刚复制过时不因鼠标移开而收起

这条例外的信号来自**剪贴板监听**，不是键盘监听。早先这里挂的是
`NSEvent.addGlobalMonitorForEvents(matching: [.keyDown])` 直接监听 `⌘C`，
而那个监听需要**「输入监控」权限**（和辅助功能是两个独立授权），
没授予时它只是静默不工作——于是这条例外悄悄失效，用户看到的是
「`⌘C` 之后按钮一闪就没了」，而且怎么查都查不出原因。
「剪贴板变了」本来就是「用户复制过」的准确含义，还不需要任何额外权限。

这几条直接决定这个功能会不会烦人。

**位置必须在「出现的那一刻」现取，不能用调用方手里的坐标。** 这是踩过的坑：
`mouseUp` 时记下鼠标位置，但按钮要等 `await reader.read()` 跑完才出现，
而这条链路里有 AX 查询窗口标题、模拟 `⌘C` 取词，实测几十到几百毫秒。
等按钮出现时用户的手早就动了，按钮于是落在光标**之外**，
紧接着的 `mouseMoved` 立刻把它收掉——表现就是「**显示一下就消失**」。

配套的两个数也是从同一个 bug 里定下来的：

| 参数 | 值 | 为什么 |
|---|---|---|
| `hoverPadding` | 40pt | 原为 24pt，而按钮摆在光标右下 40pt 处，**光标往上移 14pt 就出界**。按代码常数复算，最紧方向的余量从 12pt 提到 28pt |
| `mouseMoveGrace` | 0.6s | 按钮出现后的余动期，这期间不理会「鼠标移开」 |

## 诊断日志

出问题时的第一件事是看日志。**不要用 `log show`**，两个原因都会让你白查：

1. 受限环境里它直接拒绝运行：`log: Cannot run while sandboxed`
2. **zsh 里 `log` 是个内建命令**，不写绝对路径会被 shell 吃掉、静默返回空。
   看上去就像「应用一条日志都没打」——曾因此把一个正常的程序误判成
   「压根没跑起来」，排查方向整个跑偏。

所以关键状态同时落一份纯文本：

```bash
cat ~/Library/Application\ Support/Shiju/diagnostics.log
```

每次启动清空，长这样：

```
拾句 诊断日志（每次启动清空）

09-20 13:27:23.382  全局监听已注册 5/5 个
09-20 13:27:23.382  启动：辅助功能权限未授予，可执行文件 /Applications/拾句.app
09-20 13:28:01.117  检测到拖拽选择结束（位移 132pt）
09-20 13:28:01.180  取词耗时 63ms，12 字
09-20 13:28:01.181  显示悬浮按钮：位置 812,430 尺寸 74×30
09-20 13:28:04.203  收起悬浮按钮：鼠标移开（离按钮中心 -52,18pt，容差 40pt）
```

`install.sh` 装完会自动读这一行权限状态并告诉你。

**一个容易误判的组合**：日志里能看到 `检测到拖拽选择结束`，但后面再没有别的行——
这不是取词卡住了，而是**权限没授予**。因为鼠标类全局监听**不需要**辅助功能权限，
照样会收到事件；真正需要权限的是后面的 AX 取词。所以
`放弃取词：辅助功能权限未授予` 这行会把原因说清楚。哪一步断了，问题就在那一步。

## 签名与辅助功能权限

这两件事绑在一起，而且**踩过一次很贵的坑**，单独写一节。

### 现象

「昨天还能用，今天选中文字毫无反应」——菜单栏图标正常、进程也在跑，
但按钮永远不出现。查日志也查不出东西（因为权限没授予时，
监听器根本收不到事件，压根不会走到打日志的代码）。

### 原因

「辅助功能」授权是**跟着签名走的**，系统记的是一条代码要求（designated requirement）。
签名方式决定了这条要求里写的是什么：

| 签名方式 | 系统记的要求 | 重新编译后 |
|---|---|---|
| ad-hoc（`codesign -s -`） | `identifier "com.liulao.shiju" and cdhash H"…"` | **cdhash 变了 → 授权静默失效** |
| 本地证书 | `identifier "com.liulao.shiju" and certificate root = H"…"` | 证书没变 → 授权保留 |

ad-hoc 的 cdhash 是二进制的哈希，**每改一行代码都会变**。
所以只要用 ad-hoc 签名，每次 `make-app.sh` 之后都得去系统设置里重新勾一遍权限。

### 做法

`make-app.sh` 默认用本机一张受信任的本地开发证书签名，可用环境变量覆盖：

```bash
SHIJU_SIGN_IDENTITY="我的证书" ./Scripts/make-app.sh
```

找不到证书时会退回 ad-hoc，并明确打印警告——不会静默降级。

### 对外分发要走另一条路（`--dist`）

**这张证书只在这台机器上受信任。** 用它签出来的包发出去，
别人的机器上照样验不过（`spctl --assess` 一样 rejected），
而且 `codesign -dv` 能直接读出证书名，平白暴露本机环境。

所以构建脚本分两种身份：

```bash
./Scripts/make-app.sh          # 自己用：本机证书，辅助功能授权能留住
./Scripts/make-app.sh --dist   # 发出去：ad-hoc，包里不带本机痕迹
```

两种签名对 Gatekeeper 的**结果**是一样的（都拦），差别只在包里带不带本机信息。
分发时用户要走的那条路是**去掉隔离属性**，不是「右键打开」：

```bash
xattr -dr com.apple.quarantine /Applications/拾句.app
```

`com.apple.quarantine` 才是 Gatekeeper 拦截的触发条件——本机构建的文件没有它，
所以在开发机上永远复现不出来「已损坏」这个现象。本地可以完整模拟：

```bash
xattr -w com.apple.quarantine "0083;$(printf '%x' $(date +%s));Safari;" /tmp/t/拾句.app
spctl --assess --type execute -vv /tmp/t/拾句.app   # → rejected（预期）
open /tmp/t/拾句.app                                 # → 起不来
xattr -dr com.apple.quarantine /tmp/t/拾句.app && open /tmp/t/拾句.app   # → 起来了
```

`--assess` 只说明 Gatekeeper 的态度，**要真的 `open` 一次**才算验完。

想建一张专属证书的话，注意两个坑：

- **macOS 自带的 `openssl` 是 LibreSSL，不支持 `-addext`**，会被静默忽略，
  签出来的证书没有 codeSigning 扩展、`security find-identity -p codesigning` 里看不到。
  要用配置文件（`x509_extensions`）来写扩展。
- 建完之后还得让系统信任它（`security add-trusted-cert -p codeSign`），
  **这一步需要交互授权**，在受限环境里会被直接杀掉。Keychain Access 里
  手动设「始终信任」也一样。所以本机直接复用了已有的那张证书。

### 权限没授予时怎么看出来

菜单栏图标会变成 **「拾!」**（正常是「拾」），鼠标悬停有说明，
**点一下会弹出说明并带你去授权页**。

这里刻意**不在启动时弹模态框**：`runModal()` 会阻塞主线程，菜单栏图标点不动、
权限轮询也停摆——而「勾上就自动生效」恰恰依赖那个轮询。
启动时只调系统的授权引导（它负责把应用登记进「辅助功能」列表）。

授权勾上之后**会自动生效，不需要重启**——应用每 2 秒看一次权限状态，
一旦变成已授予就重新注册全局监听（系统不会自己开始投递事件）。

```bash
cat ~/Library/Application\ Support/Shiju/diagnostics.log   # 看权限状态
```

如果列表里**已经有「拾句」并且是勾上的、但仍然不工作**：那多半是旧版本的残留记录
（换过签名方式或换过路径）。用列表下方的「−」删掉再重新添加一次。

## 取词用的开源库

核心取词能力来自 [SelectedTextKit](https://github.com/tisfeng/SelectedTextKit)（MIT 许可），
它解决了「在任意应用可靠拿到选中文本」这个最难的部分，内置多级降级策略、
剪贴板备份还原、提示音静音。

```swift
try await SelectedTextManager.shared.getSelectedText(strategy: .auto)
```

## 已知限制

- **Canvas 渲染的应用读不到选区**（Google Docs、Figma、部分 Java 应用）。
  这是物理限制，不是 bug。
- 浏览器链接只覆盖 Safari / Chrome / Edge / Arc，且**要过一次「自动化」授权**。
  取 URL 走 AppleScript，慢且第一次会弹授权框，所以它被放在按钮出现**之后**：
  拖拽路径有 1.2s 上限、快捷键路径 3s，超时就放弃——链接只是卡片上的装饰，
  不值得让人干等。快捷键路径因为内容已经落库，URL 是事后回填到数据库的
  （面板不主动刷新，下次打开自然就有）。
- **键盘选择（`⇧`+方向键、`⌘A`）本身不触发按钮**。按钮的位置跟着鼠标走，
  而这类选择没有有意义的锚点，鼠标可能停在屏幕另一头，按钮会落在离正文很远的地方。
  鼠标类的触发只认「划过一段」和「双击/三击」两种带位置的选择动作。
  （`⌘C` 是另一回事：它有明确的「用户要这段内容」意图，而且剪贴板里带着内容本身，
  所以走剪贴板路径触发，见「复制也是一次收录意图」。）
- 搜索用 `LIKE` 而非 FTS5：FTS5 的中文分词不可用（`unicode61` 会把整串汉字
  当作一个 token，`trigram` 又要求查询至少 3 字符，而中文两字查询极常见）。
  当前量级下 `LIKE` 全表扫描在毫秒级。
- 敏感应用忽略名单目前硬编码在 `Capture.swift`（含拾句自己），尚未接偏好设置界面。
- **松手到按钮出现有几十到几百毫秒的延迟**。取词链路上有两件慢事：
  AX 查前台窗口标题、模拟 `⌘C` 读剪贴板（浏览器 URL 已移出关键路径）。
  按钮的位置已经不受它影响（现取坐标），但「按下去到看见」的手感仍受它影响。
- **本机起不了无头 Chrome**（沙箱限制，加 `--no-sandbox` 后仍被 SIGKILL），
  所以面板的验证走 jsdom（见「测试」），而不是真实浏览器。
  jsdom 不做布局，因此它**只覆盖逻辑与消息契约**；
  布局与几何改由 `test-layout.sh` 在真 WebKit（WKWebView）里量，
  视觉观感仍建议实机打开面板确认（`snapshot-panel.sh` 出的图可作参考，
  但它跑在离屏窗口里、冻住了动画，不等同于真机观感）。
